- Run from this folder: `uv run --env-file .env --package lens-hermes-agent-<simple|swarm> <simple|swarm>/main.py`. Both set `HERMES_HOME` to `home/` before importing Hermes.
- Hermes refuses to build wheels, so `vendor/hermes-agent` is an editable path source cloned at the commit in `README.md`; keep that commit, the hermes-otel `--ref`, and the README in sync.
- hermes-otel declares its entry point under `hermes.plugin`, but Hermes scans `hermes_agent.plugins`, so a pip install is never discovered. It is installed as a directory plugin into `home/plugins/hermes_otel` instead (gitignored), with deps in `home/installs`.
- `.python-version` must resolve to a GIL CPython 3.14: hermes-otel's dependency venv mixed into a free-threaded 3.14t interpreter segfaults importing `psutil`.
- `home/plugins/model-providers/litellm` registers the `litellm` provider whose `build_client_kwargs_extras` supplies the `httpx` gateway transport (Hermes pins `openai<3`). hermes-otel spans are never current, so the transport attaches `get_current_traceparent(HERMES_SESSION_ID)`; without the session key concurrent subagents share one ContextVar stack and attempts nest under the wrong `api.*` span.
- Top-level `delegate_task` always runs in the background. `swarm` waits on `tools.async_delegation.active_count()` and feeds results back with `continue_quiet_notify_completions`, as `hermes -z` does; exiting earlier leaves the subagent spans unended and unexported.
- Subagent turns are `agent` spans named `hermes-agent` under `subagent.<role>`; the litellm traces `hermes` rule renames them to the role and folds them into the dispatch span, so Lens attributes their calls and spend to the role. It also treats each `llm.<model>` turn span as a chain, leaving `api.<model>` as the model call
